### Known issues (pending-plan tasks that carry real gaps)

**1. (Task 8 — pending) `overlay_opacity` serialization precision drift — REAL BUG**
`src/config/config_settings.c:613`
```c
snprintf(buf, sizeof(buf), "%.2f", s->overlay_opacity);
```
The YAML exporter truncates `overlay_opacity` to 2 decimals. Any value not on a
0.05/0.01 grid (e.g. `0.3333` accepted by validation at L155: `0.0–1.0`) is
corrupted on save→load. Masked today because `tests/test_settings.c` roundtrip
assertions use `assert_float_equal(..., 0.001)` tolerance (L110/126/157/181), so a
`0.3333`→`0.33` roundtrip still passes. Fix = raise export format precision (e.g.
`%.4f` or round-trip-safe) + add a non-grid precision roundtrip case to `test_settings.c`.

**2. (Task 9 — pending) identify connect-time orchestration NOT wired into production**
`src/identify/identity.c`, `src/identify/assign.c` are built and unit-tested
(`test_identity`, `test_assign`, `test_order_restore`, `test_identity_downgrade`),
but **no `cbx_identify_*` call exists in any production source**. Verified with
repo-wide grep of `src/` (excluding the `src/identify/` dir itself): only
`cbx_assign_*` lookup/cycle helpers are imported, and only by overlay widget code
(`src/overlay/profile_cycle.c:13`, `src/overlay/grid_render.c:16`,
`src/overlay/close.c:14`). The production connect/hotplug path
`src/app/overlay_service.c` (InputPlumber hotplug at L1056, reconcile at L1338)
never invokes identification/tie-breaking orchestration (SPEC §6.2–6.3, §10.3).
This is a genuine integration gap the pending task targets.
